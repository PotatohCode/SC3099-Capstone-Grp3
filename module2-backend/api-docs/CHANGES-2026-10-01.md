#### Note 1: the backend address
Next.js bakes `NEXT_PUBLIC_*` into the JavaScript at build time, so
`192.168.64.4` only works on one teammate's network (elsewhere, e.g.
"Creating account…" hangs forever). With the `PUBLIC_HOST` default, testing
from a phone means setting `PUBLIC_HOST` to your own LAN IP. Change the
frontend and the CORS lines together, or browsers get blocked.

## When you're done: tell the backend owner

These backend switches are **off** until your side ships, then get turned on:

| Switch | Turned on (`flag`) after |
|---|---|
| `CONSENT_ENFORCEMENT` | M1 sends consent |
| `DEVICE_BINDING_ENFORCEMENT` | M1 uses a random per-install fingerprint |
| `LIVENESS_CHALLENGE_ENFORCEMENT` | M1 sends challenge bursts **and** M3 returns `challenge_passed` |

Problems: contact the Module 2 (backend) owner with the `X-Request-ID`
header of the failing response.
